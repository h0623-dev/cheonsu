# B안 전투 원화 제작 입력

승인 범위는 아군 21명·일반 적 37종·보스 9종의 기본형 67종이다. 승인된 B안 콘셉트 보드를 캐릭터 스프라이트로 잘라 쓰지 않고, 같은 외형의 투명 전신 원본을 별도로 저작한다. 22개 시트는 **행마다 캐릭터 한 명**, 열마다 `recover`, `strike`, `skill-a` 순서다. 일반 적 마지막 `enemy-13` 시트는 한 명의 세 자세를 **3행×1열**에 세로로 담아 넓은 망토 사이의 투명 여백을 확보한다.

`sourcepack.json`의 `anchors: null`, `authoringComplete: false`는 제작 대기 상태이며 게임에 연결된 대체 좌표가 아니다. 원본과 좌표가 준비되지 않은 입력은 제작기가 거부한다. 원본을 보며 위치·윤곽을 지정하는 일은 이번 아트 저작 과정이며, 게임 수정 후 별도 QA를 실행하는 절차가 아니다.

## 입력 순서

1. 이미지 생성 도구로 각 원본을 실제 알파가 있는 PNG로 제작하고 `sources/`의 해당 경로에 저장한다. 배경·바닥·큰 폭발은 인물 원화에 굽지 않는다. 전신·무기 끝·장비·의상이 모두 보이고 각 셀 사이에 충분한 투명 여백이 있어야 한다. 세 자세는 별도로 그린 서로 다른 동작이어야 한다.
2. 작성자가 원본의 각 자세에서 손잡이·무기 끝·방출점과 필요한 활·채찍 윤곽을 지정한다. 셀의 `anchors`와 필요시 `bodyHeight`, `box`를 입력한다. 일반적인 좌표계는 `cell-fraction`이다.
3. 시트 원본과 모든 셀의 저작 좌표가 완성되면 해당 `authoringComplete`를 `true`로 바꾼다. 제작기가 아직 실행되지 않았으면 생산 완료라고 기록하지 않는다.
4. 부모 에이전트가 원화 생산 착수를 결정한 뒤에만 제작기를 실행한다. 일부 캐릭터를 생산할 때 `--only=hero,bram,lina`처럼 지정할 수 있다. 기본 실행은 67종 모두를 요구한다.

```sh
node scripts/prepare-style-b-art.mjs
node scripts/prepare-style-b-art.mjs --only=hero,bram,lina
```

이 명령은 산출물 제작이다. 테스트·린트·브라우저·검증용 빌드·완성 파일 대조를 함께 실행하지 않는다. 기존 자동 Actions와 서명·배포 보호도 변경하지 않는다.

## 좌표와 필드

- 시트: `key`, 저장소 상대 `sourcePath`, `rows`, `columns`, `anchorSpace`, `authoringComplete`, `cells`.
- 셀: `id`, `name`, `pose`, `row`, `column`, `anchors`. 기본형만 허용하며 `__form`, `__promoted` 등의 전직은 제작 대상이 아니다. 실반은 canonical `sylvan` 또는 자산 별칭 `silvan`을 사용한다.
- 기본 셀 영역은 실제 원본 폭·높이를 행·열로 나눈 정수 경계다. 불균일 배치라면 `box: {left, top, width, height}`에 원본 픽셀 영역을 명시하거나, `sourceRect: [left, top, width, height]`에 **원본 전체의 0~1 비율** 영역을 저작한다. 실제 투명 여백을 경계로 삼아 다른 인물은 포함하지 않고 전신과 무기 끝을 모두 담는다. `box`가 있으면 `sourceRect`보다 우선한다.
- `anchorSpace: "cell-fraction"`: 점 `[x, y]`는 해당 셀 왼쪽 위 `[0, 0]`, 오른쪽 아래 `[1, 1]`을 기준으로 한다. 사용자 지정 `box`나 `sourceRect`가 있으면 **그 영역 안의 비율**이며 원래 등분 격자의 비율이 아니다. `cell-pixels`는 이 영역 안 픽셀, `sheet-pixels`는 원본 전체 픽셀이다. 셀별 `anchorSpace`가 시트 설정보다 우선한다.
- `bodyHeight`는 선택 항목이다. 무기·날개·머리 장식을 제외한 같은 몸 기준점 사이의 세로 길이를 세 자세 모두에 저작하면, 다른 자세에서 몸 자체가 커지거나 작아지지 않도록 배율을 보정한다. 단위는 좌표계와 같으며 `cell-fraction`이면 셀 높이의 비율이다. 생략하면 같은 시트의 세 자세에 동일한 등방 배율을 쓴다.
- `isolateSilhouette: true`는 원본에서 배우끼리 떨어져 있지만 직사각형 영역만 겹치는 셀에 쓰는 선택 항목이다. 이전 전투 원화 제작기의 `splitSilhouettes`를 그대로 재사용해 연결 영역을 원래 행·열의 배우에 나누고, 이웃 배우와 연결된 창·도끼 조각을 해당 셀에서 제외한다. 원본에서 전신·무기가 다른 배우와 실제로 이어졌다면 이미지 생성 도구로 원본을 다시 저작해야 한다. 새 팔다리·무기·자세를 합성하는 기능이 아니다.
- `reviewMethod`는 셀 또는 시트에 저작 방법·가려진 부위·근사치의 한계를 적는 선택 항목이다. 최종 출력의 정밀 실측이나 후속 검증으로 과장하지 않는다.

앵커의 필수 필드는 `kind`, `grip`, `tip`이다. `focus`는 실제 검 접촉점 또는 화살·마법 방출점이다. 생략하면 `tip`을 사용하므로, 화살의 시작과 끝이 필요한 활은 반드시 올바른 `focus`도 지정한다. 검을 쥔 손과 검 끝은 각각 검 손잡이와 실제 금속 끝에 둔다. 마법 광원은 허공 좌표로 가정하지 말고 원화의 지팡이·책·손과 연결한다.

- 지원 무기 종류: `blade`, `spear`, `axe`, `hammer`, `shield`, `dagger`, `claw`, `whip`, `fist`, `bow`, `crossbow`, `cannon`, `focus`, `staff`, `book`, `music`.
- 활: `bow: {upper, lower, points: [[x,y], ...], arrowVisible}`. `points`는 실제 활 외곽을 따라 위에서 아래로 지정한다. 두 제어점으로 표현할 때만 `curve: [[x,y],[x,y]]`를 대신 쓸 수 있다. `grip`은 활을 쥔 손, `focus`는 당긴 손/깃 쪽 화살 시작, `tip`은 촉 끝이다. 화살을 아직 들지 않은 자세는 `arrowVisible: false`를 쓴다.
- 채찍 등의 구부러진 무기: `pathPoints: [[x,y], ...]`.
- 쌍검·보조 무기: `secondary: {grip, tip, points?}`.
- 책: `bookCenter: [x,y]`.

숫자 예시는 좌표 입력 문법을 설명하기 위한 것이며 실제 그림의 좌표로 사용하지 않는다.

```json
{
  "id": "hero",
  "name": "카일",
  "pose": "strike",
  "row": 0,
  "column": 1,
  "anchors": {
    "kind": "blade",
    "grip": [0.55, 0.54],
    "tip": [0.83, 0.39],
    "focus": [0.83, 0.39]
  }
}
```

## 생산 시 보존과 동기화

- 기존 `characters-v2` 47종과 `characters-v3` 기본형 20종의 **동일한 세 WebP 경로만** 새 원화로 제작한다. 나머지 다섯 자세·전직 65형·지도·대기·후면·대화·보행 원화를 열거나 다시 인코딩하지 않는다. 기존 매니페스트 항목도 전체 대입하지 않고 선택한 자세만 수정한다.
- 새 원본을 잘라 512×512 투명 프레임에 등방 배치한다. 기존 recover 높이를 기준으로 삼으며, 출력 버퍼 인코딩 중 알파 영역·발 기준·배치 경계·SHA를 한 번에 제작한다.
- 8개 자세 전체의 기존 경계 메타데이터와 새 세 자세의 경계를 함께 사용해 표시 배율을 정한다. 새 recover로 기준 높이가 바뀌어도 기존 다섯 자세의 몸 크기를 불필요하게 키우지 않는다. 기존 `skills`/`skill`의 배율과 발 오프셋도 같은 공식으로 갱신한다.
- 기존 47종의 새 접촉 좌표는 매니페스트와 `skillWeaponAnchors.json`에 함께 등록한다. 신규 20종의 접촉 좌표는 원화와 SHA가 묶인 `reviewedSkillWeaponAnchors.json`에 수동 저작 근삿값으로 기록하고, 직접 실측했다고 표시하지 않는다.
- `cinematicFrameBounds.json`의 선택한 세 자세만 제작 중 픽셀 경계로 갱신한다. 실반의 canonical/자산 별칭도 함께 갱신한다. 전체 132종을 다시 읽는 경계 생성기는 추가로 실행하지 않는다.
- `production-report.json`에는 원본 영역·정규화·배치·경계·좌표·출력 SHA·보존한 자세의 기존 메타데이터가 남는다. 모든 선택 입력을 준비한 뒤 첫 게임 파일을 쓴다. 보고서는 아트 생산 기록이며 검사 통과 증거가 아니다.
