# 1.99.137 Android 버튼 겹침 수정

## 원인과 수정

사용자 사진은 Android 최근 앱/홈/뒤로 버튼이 이동 후 전투 명령 위에 겹친 상태입니다. Capacitor 7의 `android.adjustMarginsForEdgeToEdge` 기본값이 `disable`이고, 기존 명령창은 `env(safe-area-inset-bottom)`에만 의존하고 있었습니다. Android WebView에서 이 값이 0인 경우 시스템 내비게이션 영역을 침범합니다.

- 새 APK 336: Capacitor의 `adjustMarginsForEdgeToEdge: auto`를 활성화합니다. Android 15 이상에서 시스템 바/디스플레이 컷아웃의 실제 크기만큼 WebView 여백을 조정합니다. 이전 Android는 기존 OS 창 맞춤을 유지합니다.
- 기존 APK 335: 새 JS API 없이 `LiveUpdate.getVersionCode()`로 설치 앱 버전을 식별합니다. OTA만 받은 앱에는 하단 56 CSS px, 가로 모드 양쪽 56 CSS px의 보수적인 보호 여백을 둡니다. 이는 실제 inset 측정이 아닌 구형 APK용 호환 보완입니다.
- 웹 브라우저는 Android용 고정 여백을 사용하지 않습니다. 새 APK는 중복 상단 여백도 제거합니다.
- 취소/공격/스킬/아이템/대기는 고정된 마지막 행에 유지하고, 긴 대상 목록 부분만 스크롤합니다. 5개 명령일 때 아이콘 위/글자 아래 배치로 좁은 화면의 글자 잘림을 방지합니다.
- 가로 화면에서 기존 스타일의 이동 후 명령창이 새 명령창 뒤로 일부 드러나던 중복 표시도 차단합니다.
- 스킬/아이템 대화상자도 구형 APK의 시스템 버튼 영역을 피하며, 지도 자동 시점은 실제 명령창 높이를 고려합니다.
- 행동 횟수, 스킬, 아이템 소비, 저장 형식은 변경하지 않았습니다.

## OTA 호환성 검토

이번 Android 변경은 화면 영역 설정뿐이며 네이티브 API/플러그인/저장 접근 방식/서명 키는 그대로입니다. 기존 APK에 CSS 호환 경로가 있으므로 최소 지원 버전을 335로 유지했습니다. `docs/update-native-baseline.json`에 새 기준 해시와 검토 이유를 기록했습니다. APK 335와 336 모두 같은 서명 웹 패치를 받을 수 있습니다. 일반적인 네이티브 API 변경에는 여전히 최소 APK 버전 갱신이 필요합니다.

## 확인 방법

1. Android 3버튼 내비게이션에서 아군을 선택하고 빈 칸으로 이동합니다.
2. 취소/공격/스킬/아이템/대기 전체가 시스템 버튼 위에 위치하는지 확인합니다.
3. 공격 선택 중에도 다른 명령이 눌리고 스킬/아이템 창이 열리고 닫히는지 확인합니다.
4. 이동 취소 시 좌표/행동권/아이템 수가 보존되는지 확인합니다.
5. 가로/세로 전환 및 제스처 내비게이션에서도 같은 절차를 확인합니다.

`node scripts/verify-navigation-overlap.mjs`는 구형/신형 네이티브 브리지를 모의하고 시스템 버튼 영역을 DOM 오버레이로 재현하여 실제 포인터 클릭과 버튼 경계를 검사합니다. 실제 기기 또는 에뮬레이터를 대신하는 검사는 아닙니다.

Android 근거: https://developer.android.com/about/versions/15/behavior-changes-15
