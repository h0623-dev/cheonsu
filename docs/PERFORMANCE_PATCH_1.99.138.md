# 1.99.138 화면 전환과 전장 이동 성능 개선

## 변경 내용

- 스테이지/출전 인원별 읽기 전용 미리보기를 재사용합니다. 적 요약과 위험도 표시가 같은 맵의 배치를 반복 생성하지 않습니다. 실제 전투 시작은 별도로 새 유닛을 생성하므로 HP/행동 상태가 다음 전투로 새지 않습니다.
- 전체 맵 지도첩은 해당 화면에서만 준비합니다. 저장 데이터 상태 검사/복구 후보 검사는 점검 화면에서만 실행하며 검사 결과를 영구 캐시하지 않습니다.
- 지형 렌더링을 별도 memo 컴포넌트로 분리하고 정적 타일 스타일, 이동/공격 범위, 탐색 표시를 관련 상태가 바뀔 때만 계산합니다.
- 이미 화면에서 숨겨져 있던 구형 미니맵의 수백 개 DOM을 제거합니다. 현재 전장, 줌, 명령 UI와 아트는 유지합니다.
- 터치 이동은 WebView 기본 스크롤/관성에 맡깁니다. 수동 scrollLeft/scrollTop과 충돌하지 않으며 pointercancel은 이동/공격으로 처리하지 않습니다.
- 마우스 드래그는 requestAnimationFrame당 한 번 두 축을 함께 갱신합니다. 드래그 시작/종료마다 지형 전체의 스타일을 무효화하던 클래스 변경을 없앴습니다.
- 피격 흔들림은 전장에만 적용해 명령 버튼/저장 안내가 함께 흔들리거나 화면 밖으로 밀리지 않습니다. 전투 시작 연출 동안 명령은 잠기며 보스 소개가 끝나면 활성화됩니다.
- 자동 패치 생명주기는 앱에서 유지하되 진행률 구독은 업데이트 UI로 옮겼습니다. 동일한 정수 진행률과 잘못된 진행률을 무시합니다. 24,001개 다운로드 이벤트가 최대 101개 진행 상태로 줄고 게임 루트는 다시 그리지 않습니다.

## 측정

동일 PC, Edge headless, 세로 390x844, CPU 4배 감속, production 빌드, 새 독립 브라우저 저장소, 1장 조건입니다. 원시 요약은 `performance-1.99.138.json`입니다.

| 항목 | 1.99.137 | 1.99.138 |
| --- | ---: | ---: |
| 원정 지도 전환 중 메인 스레드 작업 | 1,646ms | 692ms |
| 전장 4회 드래그 중 스타일 재계산 | 564ms | 37ms |
| 드래그 프레임 간격 p95 | 50ms | 16.8ms |
| 드래그 중 50ms 초과 작업 | 9개 | 0개 |
| 전장 DOM 요소 | 1,532개 | 1,182개 |

원정 지도 작업량 약 58%, 드래그 스타일 계산 약 93% 감소입니다. 측정 스크립트의 전체 경과 시간에는 Playwright 대기, 초기 이미지/버튼 안정화, 연출 시간이 포함되므로 작업 시간과 구분합니다. 첫 진입과 모달 표시의 긴 작업은 아직 남아 있습니다. 모든 장면/휴대폰에서 끊김이 완전히 사라졌다는 의미는 아닙니다.

재현: `npm run build` 후 `node scripts/verify-performance.mjs`. 5188 포트가 비어 있어야 하며 보고서/CPU 프로파일/화면은 무시된 `tmp/performance-qa`에 생성됩니다.

## 호환성과 배포

- 저장 키와 형식, 행동/이동 규칙, 맵 배치 결과, 아트 해상도는 변경하지 않습니다.
- Android 337 / 1.99.138. 네이티브 API 변경 없이 OTA 최소 호환 335를 유지합니다.
- 기존 자동 패치 지원 APK는 설정에서 패치 확인 후 다운로드가 끝나면 앱을 완전히 종료하고 다시 실행합니다. 앱 삭제는 필요하지 않습니다.
- 단위 검사 240개, production 전투 흐름 14개, 내비게이션 겹침 7개 화면 조건, 구형/신형 모의 APK의 실제 브라우저 터치와 마우스 드래그, 자동 패치 진행률의 게임 루트 재렌더 0회, 마을 저장 실패/재시도 검사를 포함합니다.
- 실제 Android 기기/에뮬레이터는 연결되어 있지 않아 실기기의 발열/장시간 실행/설치 및 스크롤 성능은 별도 확인이 필요합니다.
