# 천수 아이폰 Safari 실행 안내

작성일: 2026-10-06 KST

## 지원 범위와 배포 상태

아이폰의 Safari에서 천수를 실행하고 홈 화면에 추가할 수 있도록 웹 전용 실행 구성을 준비합니다. 권장 환경은 iOS 16.4 이상입니다. App Store 설치나 APK 설치는 필요하지 않습니다.

이 문서는 웹 지원 작업의 초안입니다. Railway 프로젝트와 서비스 설정을 만들었으며, 소스 연결과 배포는 대기 중입니다. 공개 HTTPS 주소, 배포 소스 커밋과 실제 호스팅 상태는 배포가 끝난 뒤 기록합니다. 현재 문서에 접속 주소가 없으므로 공개 서비스가 완료됐다고 해석하지 않습니다.

| 항목 | 상태 |
| --- | --- |
| 게임 기준 버전 | 1.99.165 |
| 웹 개정 | safari-1 |
| 기존 Android 버전 코드 | 364 |
| 웹 호스팅 | Railway `cheonsu-web` 프로젝트 / `production` 환경 / `cheonsu-safari` 서비스 |
| 현재 호스팅 상태 | 프로젝트·서비스 설정 완료, 소스 연결·배포 대기 |
| 공개 HTTPS 주소 | 배포 후 기재 |
| 배포 소스 커밋 | 배포 후 기재 |
| 아이폰 실기기 동작 | 직접 확인하지 않음 |

## 아이폰에서 실행하는 방법

1. 배포 후 제공되는 천수 웹 주소를 Safari에서 엽니다.
2. 게임을 처음 불러올 때 인터넷 연결을 유지합니다.
3. Safari의 공유 버튼을 누르고 **홈 화면에 추가**를 선택합니다.
4. 홈 화면에 생긴 천수 아이콘을 눌러 실행합니다.

홈 화면에 추가하지 않고 Safari 안에서 바로 플레이할 수도 있습니다. 소리는 브라우저 정책에 따라 화면을 누른 뒤 재생될 수 있습니다. 게임에 필요한 자료를 불러오는 동안에는 연결 상태를 유지해 주세요.

## 저장과 백업

진행도와 수집 데이터는 사용 중인 기기의 브라우저 저장 공간에 보관됩니다. 기존 Android 앱의 저장 데이터와 자동으로 연동되지 않으며, 다른 아이폰이나 다른 브라우저로도 자동 이전되지 않습니다.

평소 사용하는 Safari 환경에서 실행하고 개인정보 보호 탭은 피해주세요. Safari의 웹사이트 데이터를 삭제하거나 기기를 바꾸면 기존 저장을 이용할 수 없을 수 있습니다. **설정 → 저장 관리 → 저장 데이터 복사**로 진행도를 복사해 별도로 보관해 주세요. 기기 이동 때에는 복원 기능을 이용하며, 복원 전에 현재 저장도 먼저 보관하는 것이 좋습니다.

홈 화면 실행과 Safari 탭 실행 사이의 저장 공유를 가정하지 않습니다. 한 가지 실행 방식을 정해 사용하고, 방식을 바꿀 때에는 기존 저장 데이터를 먼저 복사해 두세요.

## 인터넷 연결과 웹 업데이트

웹 버전은 온라인 실행을 기본으로 합니다. 방문한 파일을 보관하는 캐시는 재접속을 돕는 보조 기능이며, 모든 스테이지와 에셋의 오프라인 실행을 보장하지 않습니다. iOS가 저장 공간을 정리하거나 아직 방문하지 않은 자료를 불러올 때에는 인터넷 연결이 필요할 수 있습니다.

방문한 자료의 캐시는 파일당 최대 1 MiB, 최대 96개로 제한합니다. 이 자료 캐시의 상한은 96 MiB이며, 실행 화면을 구성하는 기본 파일 캐시는 별도로 관리합니다. 이 제한은 브라우저 전체 저장 사용량이나 전체 게임의 다운로드 크기를 뜻하지 않습니다.

새 웹 버전 안내를 받으면 **현재 게임을 저장한 뒤 게임 창을 완전히 닫고 다시 실행**합니다. 플레이 중 새 파일을 즉시 적용하거나 기존 저장을 삭제해 업데이트하지 않습니다.

## Android 앱과의 분리

이번 요청은 기존 Android APK에 영향을 주지 않고 아이폰에서 실행할 수 있는 웹 경로를 추가하는 작업입니다. 기준 게임은 1.99.165이며 Android 버전 코드는 364를 유지합니다. 기존 APK와 공개 Android 서명 OTA 채널도 이번 웹 작업으로 변경하거나 다시 배포하지 않습니다.

기존 게임 `App`을 웹 실행 진입점에서 재사용합니다. 웹 전용 화면 대응과 배포 설정은 `web/` 아래에서 관리하며, 이번 지원을 위해 `src/`, `public/`, `android/`, 패키지 파일 및 기존 GitHub Actions 워크플로를 변경하지 않습니다.

## 웹 제작과 호스팅 구성

웹 전용 진입점은 `web/index.html`, `web/main.jsx`, `web/safari.css`입니다. 웹용 빌드 스크립트, 서비스 워커와 정적 파일 서버도 `web/`에서 관리합니다. Railway 실행 구성은 파일 기반 설정 대신 실제 서비스 설정에 적용합니다.

제작 명령은 저장소 루트에서 실행하는 다음 명령입니다.

```sh
node web/build.mjs
```

결과는 `tmp/safari-dist`에 생성합니다. 기존 Android용 제작물과 웹 제작물의 경로를 분리합니다. 호스팅에 필요한 제작 빌드는 요청한 웹 산출물을 만드는 작업으로 수행하며, 별도의 검증용 빌드로 취급하지 않습니다.

Railway에 적용한 서비스 설정은 다음과 같습니다.

| 설정 | 값 |
| --- | --- |
| 프로젝트 | `cheonsu-web` / `e0558871-b768-46df-981f-5285a05721d5` |
| 환경 | `production` / `25095d6f-8504-44c0-bbf2-6e308fa9aba4` |
| 서비스 | `cheonsu-safari` / `237d0382-4d46-41b8-ab1e-6f4bded5e075` |
| 빌더 | Railpack |
| 제작 명령 | `node web/build.mjs` |
| 실행 명령 | `node web/server.mjs` |
| 서비스 상태 경로 | `/healthz` |
| 시작 대기 제한 | 120초 |
| 변경 감지 경로 | `web/**` |
| 메모리 | 0.5 GB |
| CPU | 1 vCPU |
| Node 런타임 | Node 24 변수 설정 예정 |

이 표는 서비스 설정 반영 상태이며 배포 성공을 뜻하지 않습니다. 공개 주소와 배포 결과는 소스 연결 및 실제 배포가 끝난 뒤 기록합니다.

## 이번 작업의 확인 범위

사용자의 검증 생략 지시에 따라 에이전트가 수정 후 테스트, 린트, 스모크 검사, 브라우저·화면 QA, 아이폰 실기기 검사 또는 아티팩트 대조를 직접 실행하지 않습니다. 호스팅 배포 상태는 실제 배포 결과가 나온 뒤 이 문서에 기록합니다. 제작이나 배포가 성공하더라도 아이폰 실기기 동작까지 확인했다는 의미는 아닙니다.

사용자 지시에 따라 수정 후 별도 검증은 실행하지 않았습니다.
