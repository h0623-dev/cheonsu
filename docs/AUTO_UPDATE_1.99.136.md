# 천수 자동 패치 운영

## 휴대폰 이용

- 최초 1회 `cheonsu_1.99.136_update_debug.apk`를 기존 앱 위에 설치합니다. 기존 앱을 삭제하지 마세요.
- 이후 앱 실행 또는 다시 활성화 시 15분 간격 제한으로 서명된 새 패치를 확인합니다.
- 자동 다운로드가 기본값입니다. 전투를 중단하거나 강제로 재시작하지 않습니다.
- 완료한 패치는 앱을 완전히 종료하고 다시 실행할 때 적용합니다. 시작 화면에서는 `지금 적용`도 가능합니다.
- 설정의 `게임 업데이트`에서 다운로드 진행률, 패치 내역, 자동 다운로드 여부를 확인할 수 있습니다.
- 전체 웹 번들을 받는 방식입니다. 데이터 요금이 발생할 수 있으므로 큰 패치는 Wi-Fi 사용을 권장합니다. 변경 파일만 받는 차등 패치는 이번 버전에 포함하지 않았습니다.
- 인터넷 연결이나 여유 공간에 문제가 있으면 기존 게임을 계속 실행합니다. 다운로드 실패는 다음 확인 때 재시도합니다.
- 새 패치가 30초 안에 초기 화면을 시작하지 못하면 APK 내장 버전으로 복구하고 실패 패치를 차단합니다. 저장 파일은 삭제하지 않습니다.
- 앱 권한, Android 플러그인, 네이티브 구조 변경에는 새 APK가 필요합니다. 게임 패치와 구분해서 표시합니다.
- 저장은 기기 내부입니다. 자동 패치는 클라우드 저장이나 기기 간 저장 동기화가 아닙니다.

## 배포처와 신뢰

- 사용자 승인 공개 저장소: `h0623-dev/cheonsu`.
- 채널: `https://raw.githubusercontent.com/h0623-dev/cheonsu/updates/latest.json`.
- 배포 파일: 버전별 GitHub Releases. 채널 브랜치는 게임 소스 브랜치와 분리됩니다.
- 안내 정보와 ZIP 모두 RSA-SHA256 서명으로 검증합니다. APK와 웹 코드에 공개 키를 고정합니다. 사용자가 임의 서버를 입력하는 예전 기능은 제거했습니다.
- 공개 키가 있는 Native LiveUpdate 플러그인은 ZIP 파일 바이트의 서명을 검증합니다. 파일 검증 실패 시 활성화하지 않습니다.
- 자동 패치에는 Capawesome 유료 서비스나 API 키를 사용하지 않으며 저장 데이터를 서버로 보내지 않습니다.
- 개인 키 `.update-keys/private.pem`은 Git과 전체 소스 ZIP에서 제외합니다. 절대로 GitHub, 채팅, 공개 배포 파일에 넣지 마세요.
- 다른 개발 PC에서 배포할 때는 이 개인 키를 별도의 안전한 방법으로 전달하고 `CHEONSU_UPDATE_PRIVATE_KEY_PATH`로 지정합니다. 키를 분실하면 새 APK를 통해 신뢰 키를 교체해야 합니다.
- 다른 PC에서 기존 앱 위에 설치할 APK를 만들 때는 Android 서명 키도 같아야 합니다. 현재 개발용 debug.keystore는 소스 ZIP에 포함하지 않습니다. OTA 서명 키와 Android APK 서명 키는 서로 다른 키입니다.

## 이후 패치 배포 절차

1. 코드와 `package.json`, `src/App.jsx` 저장 버전, Android 버전, 서비스워커 버전, `docs/update-notes.json`을 함께 갱신합니다.
2. 테스트, 화면 검증, `npm run android:apk`를 실행하고 최종 APK의 버전, 기존 서명, 웹 파일 해시를 검증합니다.
3. APK를 `cheonsu_<버전>_update_debug.apk`로 복사합니다. `npm run update:package`로 서명된 OTA와 안내 정보를 만듭니다.
4. `npm run package:source`를 실행하고 최종 소스를 커밋한 뒤 GitHub에 push합니다.
5. `npm run update:publish`를 실행합니다. 현재 PC의 GitHub 인증을 사용합니다. 토큰을 앱에 포함하지 않습니다.
6. 배포 스크립트가 OTA/APK/소스 업로드 해시와 익명 접근을 검증한 뒤 채널을 마지막에 갱신합니다. 이미 배포된 같은 버전 파일은 덮어쓰지 않습니다.
7. 공개 채널 서명과 버전을 확인합니다. 실패 시 채널 변경 여부를 확인하고 같은 버전/같은 파일로 재시도합니다.

`npm run update:package`는 빌드 후 소스 변경과 네이티브 구조 변경을 차단합니다. Android 구조가 변경되면 `src/data/updateTrust.json`의 최소 앱 버전을 올리고 `docs/update-native-baseline.json`을 재검토해야 합니다. 호환되지 않는 구형 APK에는 OTA 대신 APK 설치 안내를 전달합니다. 재배포가 필요한 결함은 버전 번호를 올려 수정합니다.

## 검증 범위

서명, 변조, 버전 호환, 오프라인, 실패 패치 재차단, 중복 다운로드, 저장 보존은 자동 테스트로 검사합니다. 이번 PC에는 연결된 Android 기기나 설치된 에뮬레이터가 없어 실제 휴대폰에서의 OTA 설치/복구는 별도 확인이 필요합니다. 앱을 지우지 않고 설치하고 중요한 저장은 설정에서 내보내기를 권장합니다.
