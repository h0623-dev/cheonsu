## 복원 원칙

1. 다른 대상을 지정하지 않은 **“원복”은 전체 소스 커밋 `5d0f52175792dcaf464fd870db3f6e7c313d9314`의 1.99.165 게임과 Safari 웹 지원 상태**를 의미합니다. 기준 변경은 이번 명시적 사용자 요청에 따른 것이며, 다음 명시적 기준 변경 요청 전까지 유지합니다.
2. 현재 작업과 저장을 먼저 보존합니다. 이후 플레이로 얻은 경험치·장비·진행도·수집 데이터와 Android·Safari의 현재 저장을 삭제하지 않습니다. 원복과 무관한 사용자 변경·로컬 커밋도 보존합니다. 플레이 데이터 자체 되돌리기는 별도 요청이 필요합니다.
3. 공유 Git 이력에 강제 reset/push를 하지 않습니다. 기준의 게임 코드·그림·웹 실행 구성을 새 복원 커밋으로 적용하며 이 문서와 원복 지침은 유지합니다. 저장 호환성을 지키기 위해 현재 저장을 읽는 데 필요한 호환 처리와 업데이트 신뢰 설정도 보존합니다.
4. 설치된 APK보다 높은 Android versionCode와 현재 공개 버전보다 높은 새 패치 번호를 부여합니다. 기준 APK를 재설치하거나 공개 업데이트 포인터를 과거로 낮추는 방식은 사용하지 않습니다.
5. 새 상위 버전의 최종 소스로 fresh APK를 제작하고 기존 GitHub Actions의 서명·배포 절차에 따라 signed OTA까지 공개합니다. APK·OTA 자동 검사와 공개 다운로드 검사는 기존 자동 Actions의 보호 절차로 유지합니다. 사용자 지시로 에이전트의 별도 검증은 생략하며, 자동 실행 결과를 에이전트의 직접 검사로 표현하지 않습니다. 제작·배포가 막히면 정확한 장애를 보고하고 과거 APK를 새 결과로 제시하지 않습니다.
6. Safari도 기준 동작으로 복원한 소스를 별도로 지정해 새 웹 산출물로 배포합니다. 웹 캐시 개정을 갱신하되 브라우저 저장을 지우지 않습니다. 기존 `web/` 빌드·호스팅 분리와 같은 공개 주소를 유지하며, Android 배포만으로 Safari 복원까지 완료됐다고 보고하지 않습니다. 현재 인프라·도메인·인증 정보는 과거 값으로 덮어쓰지 않습니다.
7. Android/OTA 서명은 GitHub Actions의 `cheonsu-release` 환경과 `main`에서만 수행합니다. 기존 개인 서명키·장기 토큰을 클라우드 작업으로 복사하거나 출력·요청하지 않고 공개 소스/ZIP에 넣지 않습니다. 실제 공개 OTA 채널은 별도 `updates` 브랜치의 `latest.json`입니다. `main`의 오래된 `public/updates/latest.json`만 보고 채널을 초기화하거나 다운그레이드하지 않습니다.
