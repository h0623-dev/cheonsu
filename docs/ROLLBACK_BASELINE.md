## 복원 원칙

1. 다른 대상을 지정하지 않은 "원복"은 위의 **1.99.154** 게임 상태를 의미합니다. 기본 기준 변경은 이번의 명시적 사용자 요청에 따른 것이며, 이후 패치를 배포해도 기준을 자동 갱신하지 않습니다.
2. 현재 작업과 저장을 먼저 보존합니다. 이후 플레이로 얻은 경험치/장비/진행도/수집 데이터는 삭제하지 않으며, 원복과 무관한 사용자 변경·로컬 커밋도 보존합니다. 플레이 데이터 자체 되돌리기는 별도 요청이 필요합니다.
3. 공유 Git 이력에 강제 reset/push를 하지 않습니다. 기준 커밋의 게임 코드/그림을 새 복원 커밋으로 적용합니다. 이 문서와 원복 지침은 유지합니다.
4. 설치된 APK보다 높은 Android versionCode와 현재 공개 버전보다 높은 새 패치 번호를 부여합니다. 기준 APK를 재설치하거나 업데이트 포인터를 과거로 낮추는 방식은 사용하지 않습니다.
5. 저장 호환성 및 업데이트 신뢰 설정을 확인하고 새로운 상위 버전의 최종 소스로 fresh APK를 빌드·검증합니다. APK 인증서/버전/내장 웹 파일 전체/OTA trust를 확인한 뒤 소스 push, signed OTA 포장·배포 및 공개 다운로드 검증까지 완료합니다. APK 또는 OTA 배포가 막히면 정확한 장애를 보고하며 과거 APK를 새 결과로 제시하지 않습니다.
6. Android/OTA 서명은 GitHub Actions의 `cheonsu-release` 환경과 `main`에서만 수행합니다. 기존 개인 서명키·장기 토큰을 클라우드 작업으로 복사하거나 출력·요청하지 않고 공개 소스/ZIP에 넣지 않습니다. 실제 공개 OTA 채널을 확인하며 `main`의 오래된 `public/updates/latest.json`만 보고 채널을 초기화하거나 다운그레이드하지 않습니다.
