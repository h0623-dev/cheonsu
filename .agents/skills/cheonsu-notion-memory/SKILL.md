# 천수 프로젝트 기억 읽기와 갱신

2026-10-15 KST 사용자가 새 채팅으로 옮겨도 맥락을 이어갈 인수인계와 수정 사항 발생 때마다의 Notion 갱신을 요청했습니다. `h0623-dev/cheonsu` 작업에 적용하며 다른 프로젝트의 Notion 기록을 변경하지 않습니다.

## 시작할 때

1. 연결된 Notion의 활성화 스킬 목록을 읽고 관련 스킬 **천수 개발 기억 읽기·갱신**을 읽습니다. Notion 도구 접근 상태를 확인하고 현재 제공되는 검색·읽기 도구를 사용합니다.
2. 사용자가 준 링크를 우선합니다. 링크가 없다면 **천수 개발 기억·인수인계**를 제목으로 검색해 정확한 기준 페이지를 읽습니다. 같은 이름이 여러 개라면 프로젝트와 내용을 대조하고 임의의 다른 기록을 덮어쓰지 않습니다.
3. 사용자 최신 지시, 실제 origin·HEAD·git status·버전, `AGENTS.md`, 최신 BUILD/QA/원복 문서를 확인합니다. 오래된 문서의 값을 현재 상태로 쓰지 않습니다. 기존 사용자 변경·커밋·저장과 진행도를 보존합니다.
4. 현재 요청과 진행 상태를 기록합니다. 예전 요청을 자동으로 미완료로 취급하거나 미리보기·공개 승인과 게임 적용 승인을 혼동하지 않습니다.

## 같은 페이지에 계속 반영할 때

- 매 사용자 요청, 중요한 결정·구현·장애·검사·시안 공개·릴리스 등 의미 있는 상태 변경 후와 최종 응답 전에 갱신합니다. 진행이 길면 재개 가능한 중간 상태도 기록합니다.
- 현재 요약·최근 작업·대기 결정은 최신 사실로 정리하고 이력에는 KST 시각과 변경 이유·근거를 짧게 추가합니다. 사용자 메모·관련 없는 문단·기존 이력·자식 페이지를 보존합니다.
- 기록 항목은 요청과 승인 범위, 실제 변경과 이유, 버전·브랜치·소스 및 배포 커밋, 직접/자동/이전 검사 구분, 영상·APK·OTA 링크, 장애, 미완료 결정, 다음 단계입니다.
- 페이지를 먼저 읽은 뒤 필요한 부분만 수정합니다. 매번 새 인수인계를 만들거나 전체 본문을 무조건 교체하지 않습니다. 스킬은 방법, 기준 페이지는 바뀌는 사실을 담습니다.
- 요청된 기록 저장의 성공을 확인하되 게임 테스트·린트·QA·검증 빌드를 새로 허용한 것으로 해석하지 않습니다. 기존 검증 생략 스킬과 자동 Actions 보호는 유지합니다.

## 실패와 정보 보호

- 연결·권한 문제로 쓰지 못하면 Notion 반영 완료라고 하지 말고 현재 대화에 미반영 내용과 다음 재개 지점을 남깁니다. 가능한 독립 작업은 계속하며 접근 제한을 우회하지 않습니다.
- 개인키·장기 토큰·비밀번호·개인 저장 원문·내부 추론을 기록하지 않습니다. 비공개 Notion 페이지의 URL·ID·본문을 공개 GitHub에 넣지 않습니다. 공개 저장소에는 이 스킬과 페이지 제목만 둡니다.
- 원문 전체 대화나 모델 내부 기억의 자동 복원, 작업이 없는 동안의 외부 커밋 상시 감시를 보장하지 않습니다. 새 채팅은 Notion 연결과 기준 링크/제목을 통해 읽고 이어갑니다.

## 결과 보고

같은 기준 페이지 링크와 실제 반영 상태, 다음 결정을 한국어로 간단히 알립니다. 이미 허용된 같은 페이지의 정상 갱신은 반복해서 승인을 묻지 않습니다. 문서·지침만 변경하는 커밋에는 `[skip ci]`를 사용하고 게임 버전·APK·OTA는 유지합니다.
